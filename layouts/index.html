The discrete Fourier transform in pure Go.
numpy.fft semantics, no FFTW.

go-fft computes the discrete Fourier transform of complex and real signals of any length — an iterative mixed-radix Stockham engine for lengths with small prime factors, Rader and Bluestein's chirp-z for the rest — in pure Go, with cgo disabled. It follows the numpy.fft / scipy.fft conventions: forward and inverse complex and real transforms, multi-dimensional and 2-D transforms, frequency-bin helpers, window functions and spectral helpers (PSD, spectrogram).

main.go
import "github.com/go-fft/fft"

X := fft.FFT(x)          // forward DFT of []complex128, any length
y := fft.IFFT(X)         // inverse DFT, normalized by N (IFFT(FFT(x)) ≈ x)

R := fft.RFFT(r)         // real-input DFT, non-redundant N/2+1 bins (numpy.fft.rfft)
z := fft.IRFFT(R, len(r)) // back to []float64 (numpy.fft.irfft)

// Windowing and spectral helpers:
w  := fft.Hann(n)             // also Hamming, Blackman, BlackmanHarris, Bartlett
f  := fft.FFTFreq(n, d)       // bin frequencies (numpy.fft.fftfreq)
p  := fft.PSD(sig, d)         // one-sided power spectral density (periodogram)

Why go-fft

The workhorse of signal processing, without FFTW.

The fast Fourier transform is the workhorse of signal processing, and in most languages it means binding the native FFTW3 C library. go-fft brings the numpy.fft / scipy.fft vocabulary to Go with no cgo and no FFTW: a single portable module that cross-compiles to a static binary on every target, accelerated by go-asmgen-generated SIMD where the Go assembler allows it.

🐹

Pure Go

CGO_ENABLED=0 across the org. No cgo, no FFTW, no native shims.

✅

100% test coverage

Gated in CI, differentially checked against numpy.fft.

🔢

numpy.fft semantics

The same normalization, bin layout and frequency conventions you already know.

⚡

AVX2 & AVX-512, bit-identical

On amd64 the transform's passes run as go-asmgen AVX2 kernels, and AVX-512 for large powers of two — each tested bit-identical to the Go code, because a faster transform that answers differently is not the same transform. The same Go code runs on all six 64-bit targets.

💎

The cgo-free FFT that was missing

Ruby has no cgo-free FFT (every option wraps FFTW3) and gonum/dsp/fourier's optimized assembly is amd64-only. go-fft runs on all six 64-bit Go targets, in pure Go.
